# 咪咕医生 · 猫狗健康风险分流与就医沟通

咪咕医生是一个移动端优先的本地 Web 产品：当猫或狗出现不适、疑似误食，或主人需要了解日常养护信息时，它先识别不能等待的危险信号，再帮助主人把真正影响就医判断的信息整理清楚。

产品给出的是**风险行动提示和就医准备材料**，不是疾病诊断、处方或远程医疗服务。呼吸困难、持续抽搐、意识异常、无法站立、大量出血、完全尿不出来或状态快速恶化时，应立即联系可接诊的宠物医院，不要等待线上回复。

当前版本用于本地作品演示和产品验证，仅支持猫和狗。

## 产品方向

视觉和交互围绕“暖色分诊手册”展开：

- 奶油白、纸张白和暖棕构成安静、可信的阅读底色；
- 陶土红负责品牌和主操作，杏桃色用于进度、插画与少量情绪缓冲；
- 首页使用暖色手绘猫狗主视觉，并把三段行动分流做成像问诊夹标签一样的结构化信息；
- 宋体风格标题负责识别度，系统无衬线字体承载正文，等宽标签只用于规则与状态；
- 页面以危险检查、病例资料、行动结果和沟通卡为主，不把产品包装成“AI 看病”；
- 首页和所有内页共享 `PET TRIAGE GUIDE` 品牌标识、三段行动分流和一致的安全边界。

## 当前已完成的流程

### 症状风险分流

1. **危险信号检查**：明确危险信号直接进入紧急行动页，不依赖模型。
2. **宠物资料**：采集种类、品种、年龄、体重、性别、绝育情况和病史；不确定的信息可以留空或明确选择“不确定”。
3. **症状变化**：采集开始时间、趋势、频率、精神状态、进食、饮水、排尿、排便和近期特殊情况。
4. **关键追问**：非紧急场景由 AI 补充 2–3 个最能改变风险判断的问题；服务不可用时使用固定安全问题。
5. **行动结果**：展示风险等级、判断依据、现在怎么做和立即就医信号。
6. **就诊沟通卡**：把主人填写的信息和补充回答整理成可复制给兽医的摘要。

### 三段行动分流

| 分流 | 服务端枚举 | 含义 |
| --- | --- | --- |
| 护栏下观察 | `OBSERVE_WITH_GUARDRAILS` | 当前没有明确急症信号，可记录变化，并按页面给出的升级条件继续观察 |
| 现在联系兽医 | `CONTACT_VET_NOW` | 信息不足、症状需要尽快确认，或无法安全排除风险 |
| 立即就医 | `EMERGENCY_NOW` | 已出现危险信号或可能快速恶化，不应继续等待 |

这是行动优先级，不是疾病严重程度的远程诊断。前端确定性规则只允许把风险提高，不允许把服务端结果降级。

### 误食风险

误食页面**完全使用本地确定性规则，不调用 AI**：

- 采集物品、可能剂量、距误食时间、体重和当前症状；
- 任何疑似有害摄入至少提示现在联系执业兽医；
- 已出现生命危险信号时直接提示立即就医；
- 信息不确定时采取保守分流，不根据猜测降低风险；
- 生成可复制的误食沟通摘要，并持续提醒保留包装、成分表和照片；
- 不提供盐、双氧水等家庭催吐方法，不提供药物或强行喂食建议。

### 日常健康百科

- 支持喂养、环境、行为和日常观察类问题；
- 常见快捷问题带有本地科普卡，模型未配置时仍有安全的基础说明；
- 自由问题在 AI 不可用时使用通用保守兜底；
- 涉及误食时转到误食工具，出现危险信号时转到紧急行动页。

### 紧急行动

- 显示主人刚刚确认的危险信号；
- 给出先电话确认接诊、携带资料和安全转运的行动顺序；
- 提供地图搜索入口，但不承诺医院距离、营业状态或实际接诊能力；
- 危险信号可以直接复制给医院沟通。

## 安全设计

- 危险信号、误食分流和前端最低风险线由确定性规则负责。
- AI 只负责补充追问、整理结构化结果、相关后续说明和日常百科。
- 系统提示词保存在服务端，浏览器不能提交 `system` 消息或选择模型。
- `triage_result` 必须返回严格 JSON；风险枚举、字段类型和内容长度均在服务端校验。
- 模型输出若包含自行催吐、双氧水/盐水催吐、处方式剂量、强行或针管喂食喂水等危险建议，会被丢弃。
- 结构或安全校验失败时，分流结果固定降级为 `CONTACT_VET_NOW`。
- 上游不可用、未配置密钥或返回空内容时，页面保留本地问题、风险兜底和确定性危险规则。
- 所有动态内容使用安全文本渲染，不把模型文本作为 HTML 注入。

## 本地数据与隐私

- 问诊草稿、最终病例、补充问答、已生成风险结果、误食草稿和危险信号保存在当前浏览器的 `localStorage`。
- 当前版本写入的数据使用带过期时间的封装，默认 **24 小时后失效**。
- 首页和流程页提供“清除本机记录”入口；存储不可用不会阻断危险分流。
- 项目没有账号、云数据库或服务端病例存储。
- 只有检测到服务端已配置模型时，症状资料、补充回答或百科自由问题才会在用户确认后经本地代理发送到 DeepSeek API；病例会保存当次处理模式与授权时间，聊天页再次核对，旧病例或本地模式病例不会因后来配置模型而自动外发。未配置时使用本地固定问题和保守提示。
- 不应填写宠物主姓名、手机号、地址、证件等与宠物分流无关的个人信息。

## 技术架构

```text
浏览器
├─ 静态页面与本地确定性规则
├─ 24 小时 localStorage 草稿
├─ 紧急行动 / 误食分流（不调用 AI）
└─ POST /api/assist
       │
       ▼
Python 本地代理（仅监听 127.0.0.1）
├─ 严格请求协议与服务端系统提示词
├─ 结构化结果校验和危险建议过滤
├─ 固定安全兜底
└─ DeepSeek API
```

技术栈：

- 前端：HTML、CSS、原生 JavaScript
- 本地服务：Python `ThreadingHTTPServer`
- 模型接口：DeepSeek 的 OpenAI 兼容接口
- 默认模型：`deepseek-v4-flash`，可通过服务端 `DEEPSEEK_MODEL` 覆盖
- 本地状态：`localStorage`，默认 24 小时过期

模型调用显式关闭 thinking 模式；模型名、API Key 和系统提示词不会从浏览器请求中读取。

## `/api/assist` 协议

请求必须使用 `Content-Type: application/json`，正文只能包含 `task` 和 `messages`：

```json
{
  "task": "triage_questions",
  "messages": [
    {
      "role": "user",
      "content": "猫，症状从今天开始，精神比平时差"
    }
  ]
}
```

允许的任务：

- `triage_questions` → `{"questions": ["问题一", "问题二"]}`
- `triage_result` → 对象字段：`risk`、`riskLabel`、`rationale`、`actions`、`emergencySigns`
- `triage_followup` → `{"text": "..."}`
- `wiki` → `{"text": "..."}`

消息只允许 `user` 和 `assistant`，最后一条必须是 `user`。浏览器提交 `system`、`tool`、`model` 或额外控制字段会被拒绝。

成功响应统一为：

```json
{
  "task": "wiki",
  "result": {
    "text": "..."
  },
  "model": "deepseek-v4-flash"
}
```

失败响应统一为：

```json
{
  "error": "模型服务暂时不可用，请稍后重试。",
  "code": "UPSTREAM_ERROR"
}
```

`GET /api/health` 只报告本地是否发现密钥以及当前服务端模型名，不做外部探活。

## 静态服务边界

- 静态根固定为 `api_proxy.py` 所在目录，与启动命令的当前工作目录无关。
- 只发布六个页面、`favicon.svg`、现有页面图片以及 `assets/app.js`、`assets/styles.css`。
- GET 和 HEAD 都拒绝 `.env`、`.git`、Python 源码、`tests/`、`docs/`、历史 `app.py` 和所有其他未列入白名单的路径。
- 目录列表被禁用。
- 安全响应头包括 CSP、`X-Content-Type-Options`、`X-Frame-Options` 和 `Referrer-Policy`。

`.env` 只从项目目录显式加载，不会向父目录搜索。

## 本地运行

环境要求：Python 3.10 或更高版本。当前测试环境使用 Python 3.14 时测试能够通过，但 OpenAI 依赖可能输出 Pydantic V1 兼容警告；希望避免该警告时可使用 Python 3.13。

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

编辑项目目录中的 `.env`：

```env
DEEPSEEK_API_KEY=your_api_key_here
DEEPSEEK_MODEL=deepseek-v4-flash
PORT=8000
```

启动：

```bash
python api_proxy.py
```

访问 [http://127.0.0.1:8000](http://127.0.0.1:8000)。

没有 API Key 时，静态页面、危险信号检查、误食分流、紧急行动、本地科普卡和保守兜底仍然可用；AI 追问和自由问答不会调用上游模型。

## 当前限制

- 仅支持猫和狗；没有覆盖异宠。
- 没有执业兽医在线审核，也没有完成临床有效性验证。
- 危险信号、风险阈值、误食规则和服务端提示词仍需执业兽医正式复核。
- 地图按钮只是搜索入口，不能确认最近距离、24 小时营业状态或接诊能力。
- 没有账号、云端病例、多宠物档案、通知、支付或医院目录。
- 本地 `ThreadingHTTPServer` 没有公网所需的认证、授权、TLS、限流、审计日志、监控、备份和合规数据保护。
- 不应把当前服务直接暴露到公网。若要公开部署，必须重新设计身份认证、速率限制、密钥管理、隐私政策、数据留存、内容审核、故障监控和人工升级机制。
