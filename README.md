# 咪咕医生 · 宠物健康 Web MVP

咪咕医生是一款面向宠物主的移动端 Web 产品原型：当宠物出现不适或疑似误食时，先帮助主人把关键信息说清楚，再给出风险提示与下一步行动建议。

> 本项目用于产品探索与本地演示，不提供诊断或处方，也不能替代执业兽医的线下检查。出现呼吸困难、抽搐、意识异常、大量出血等危险信号时，应立即联系宠物医院。

![咪咕医生首页插图](home.png)

## 为什么做这个产品

宠物不舒服时，主人经常面临三个问题：不知道该描述什么、不知道是否紧急、也容易被互联网上互相矛盾的信息影响。这个 MVP 将动物医学场景中的危险信号识别、结构化信息采集和 AI 追问结合起来，目标不是“AI 看病”，而是降低主人表达和分流的门槛。

## 已完成的核心流程

- **症状初筛**：先检查确定性的危险信号，再分三步采集宠物信息和症状。
- **AI 追问**：围绕持续时间、频率和伴随表现补充 2–3 个关键信息。
- **结构化结果**：按风险提示、判断依据、现在怎么做、何时立即就医展示。
- **误食风险**：记录误食物、时间、估计剂量和宠物体重；信息不足或高危时优先转诊。
- **养宠百科**：回答日常饮食、护理和行为问题，并持续展示非诊断边界。
- **紧急分流**：危险信号由规则直接触发，不依赖大模型判断。

## 产品安全边界

- 不给出确定诊断、处方药或剂量建议。
- 不建议主人自行催吐、强行喂食或自行用药。
- 危险信号使用确定性规则分流，不让模型弱化高风险。
- 高风险或信息不足时，固定建议联系执业兽医并提供医院导航入口。
- 模型输出只按纯文本安全渲染，避免把未知内容直接注入页面。
- API Key 仅由本地 Python 服务读取，不进入浏览器，也不会提交到 Git。

## 技术实现

- 前端：HTML、CSS、原生 JavaScript
- 本地后端：Python `ThreadingHTTPServer`
- 模型：DeepSeek（OpenAI 兼容接口）
- 本地状态：`localStorage`
- AI 协作：项目上下文文档、任务拆解、真机/浏览器验收、安全扫描与规则沉淀

```text
浏览器页面
   │  同源 POST /api/chat/completions
   ▼
Python 本地代理 ──── DeepSeek API
   │
   └── 密钥只保存在本地 .env
```

## 本地运行

环境要求：Python 3.10 及以上。

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

在 `.env` 中填写自己的密钥：

```env
DEEPSEEK_API_KEY=your_api_key_here
PORT=8000
```

启动：

```bash
python api_proxy.py
```

浏览器访问 `http://127.0.0.1:8000`。未配置密钥时仍可查看静态界面，但 AI 对话功能不会工作。

运行本地检查：

```bash
python -m unittest discover -s tests -v
node --check assets/app.js
python -m py_compile api_proxy.py
```

## 项目结构

```text
.
├── index.html             # 首页与产品入口
├── consult.html           # 三步症状信息采集
├── chat.html              # AI 追问与结构化风险提示
├── toxin.html             # 误食风险信息采集
├── wiki.html              # 日常养宠百科
├── emergency.html         # 确定性紧急分流
├── api_proxy.py           # 本地静态服务与模型代理
├── assets/                # 共用视觉系统与网络请求封装
├── tests/                 # 请求校验与静态页面冒烟测试
├── requirements.txt       # Python 依赖
├── .env.example           # 无密钥的环境变量模板
└── docs/ai-context/       # AI 协作上下文和产品进度
```

## 当前状态与下一步

当前版本是可本地运行和演示的 Web MVP，尚未包含账号系统、云端数据库、真实用户健康档案或公开部署。下一阶段优先级：

1. 由执业兽医复核危险信号与误食分流规则；
2. 补充可重复的前端流程测试和可用性测试；
3. 在明确隐私与数据保存策略后，再设计多宠物档案；
4. 若公开部署，增加认证、限流、监控和服务端数据保护。
