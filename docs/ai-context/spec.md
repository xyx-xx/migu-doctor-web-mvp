# 咪咕医生产品规格

> 当前基线：2026-08-28 本地 Web 演示版
>
> 支持对象：猫、狗
>
> 产品性质：风险行动提示与就医沟通工具，不是诊断、处方或远程医疗服务

## 1. 产品定位

咪咕医生帮助焦虑中的宠物主人完成三件事：

1. 先识别不能等待的危险信号；
2. 把宠物资料、症状变化和误食信息说清楚；
3. 得到明确的下一步行动，并把摘要复制给兽医。

核心价值不是“让 AI 判断疾病”，而是用确定性规则守住高风险入口，用结构化采集减少遗漏，再让 AI 在受限协议内辅助追问和整理。

## 2. 视觉与交互方向

设计概念是“暖色分诊手册”：

- 奶油白 `#FBF3EC`：页面底色与柔和环境光；
- 纸张白 `#FFFDFA`：表单、沟通卡和行动结果；
- 陶土红 `#B45C3F`：品牌、主要操作和进度，白字对比度满足普通文本 AA；
- 暖棕 `#301C18`：标题与高信任信息；
- 杏桃 `#E9A05F`：猫狗主视觉和少量识别色；
- 紧急红 `#B94B43` 只用于明确危险状态，不用来制造焦虑。

首页的记忆点是一张暖色手绘猫狗合影，并配合“观察 / 联系 / 急诊”三段分流标签。标题采用宋体风格展示字，正文使用系统无衬线字体，规则标签使用等宽字体。

所有页面共享 `PET TRIAGE GUIDE` 品牌头、统一 SVG 图标、移动端优先布局、清楚的触控目标和持续可见的非诊断边界。

## 3. 产品原则

1. **规则优先**：明确危险信号、误食和最低风险线不交给模型决定。
2. **信息未知可以承认**：不默认填写正常值，不要求用户猜年龄、体重、剂量或时间。
3. **行动优先于解释**：先告诉用户现在做什么，再解释依据。
4. **模型不能降低风险**：本地风险线只能把模型结果提高。
5. **失败时仍可用**：无密钥、超时、上游错误和非法模型输出都有本地安全路径。
6. **可交接**：最终产物应能复制给宠物医院，而不只是停留在聊天消息。
7. **数据最小化**：本地草稿默认 24 小时过期，不收集无关的宠物主身份信息。

## 4. 信息架构

```text
首页
├─ 紧急快捷入口 → 紧急行动页
├─ 症状风险分流
│  └─ 危险信号 → 宠物资料 → 症状变化
│     → 2–3 个关键追问 → 三段行动结果
│     → 就诊沟通卡 / 复制给兽医 / 开始新问诊
├─ 误食风险
│  └─ 本地确定性规则 → 联系兽医或立即就医
│     → 误食沟通摘要 / 地图搜索
└─ 日常健康百科
   ├─ 常见问题本地科普卡
   └─ 受限 AI 问答 → 危险信号或误食时转专用流程
```

## 5. 功能规格

### 5.1 首页

- 直接呈现“先判断急不急，再把症状说清楚”的产品价值。
- 提供症状风险、误食风险、日常百科三条主路径。
- 首屏提供呼吸困难、抽搐、无反应和大量出血的紧急快捷入口。
- 显示当前 AI 是否已配置；未配置时明确本地规则仍可用。
- 展示三段行动分流、安全原则、24 小时草稿和清除本机记录入口。

### 5.2 症状风险分流

#### 第一步：危险信号

覆盖：

- 明显呼吸费力、猫张口呼吸或黏膜发紫；
- 持续/反复抽搐、意识异常或叫不醒；
- 突然无法站立、行走或明显瘫软；
- 大量出血或压迫后仍无法止血；
- 频繁用力排尿但只有几滴，或完全无尿；
- 腹部突然胀大并持续干呕；
- 车撞、高处坠落、严重咬伤、卡喉或窒息；
- 状态快速恶化、疑似中暑/中毒，或呕吐腹泻到无法留住水。

任一信号被选择时，用户应停止在线填写并进入紧急行动路径。拿不准是否属于危险信号时，采取联系医院的保守提示。

#### 第二步：宠物资料

采集：

- 猫或狗；
- 品种；
- 年龄与单位；
- 体重；
- 公、母或不确定；
- 是否绝育；
- 基础疾病、正在用药和过敏史。

未知年龄、体重和其他信息允许留空或标记“不确定”。当前版本不支持其他宠物。

#### 第三步：本次症状

采集：

- 主要症状；
- 开始时间；
- 正在加重、稳定、缓解或不确定；
- 发生频率；
- 精神状态；
- 进食与饮水；
- 排尿与排便；
- 其他异常和近期特殊情况。

提交前展示所有将发送给模型的病例摘要，并明确数据传输说明。

### 5.3 AI 关键追问

- 对非紧急病例提出 2–3 个最能改变风险判断的问题。
- 优先询问危险信号、症状趋势、持续时间、精神、吃喝排泄和误食相关信息。
- 不重复已知内容。
- 模型不可用时使用三条固定安全问题，不让流程停在空白状态。
- 用户回答“不确定”属于有效答案。

### 5.4 三段行动结果

服务端只接受以下枚举：

| 枚举 | 页面动作 | 使用条件 |
| --- | --- | --- |
| `OBSERVE_WITH_GUARDRAILS` | 护栏下观察 | 信息较完整、表现轻微稳定、没有已知危险信号，并有明确升级条件 |
| `CONTACT_VET_NOW` | 现在联系执业兽医 | 需要尽快确认、疑似有较高风险，或信息不足以安全排除风险 |
| `EMERGENCY_NOW` | 立即前往可接诊医院 | 存在危险信号或可能快速恶化 |

结构化结果必须包含：

- `risk`
- `riskLabel`
- `rationale`
- `actions` 字符串数组
- `emergencySigns` 字符串数组

前端本地规则计算最低风险线；最终风险取模型结果和本地风险线中更高的一项。

### 5.5 就诊沟通卡

症状流程生成的摘要包括：

- 生成时间；
- 宠物资料和病史；
- 主要症状、开始时间与趋势；
- 吃喝、精神、排尿排便和频率；
- 其他异常和近期变化；
- AI 追问与主人回答；
- 三段风险、判断依据、行动和立即就医信号。

用户可以复制基础病例摘要或完整风险结果，也可以开始新的问诊。

### 5.6 误食风险

误食页面完全由浏览器确定性规则运行，不调用 `/api/assist`：

- 采集猫/狗、体重、疑似误食物、可能剂量、距误食时间和症状；
- 重量、剂量和时间设有输入边界，并提供“不确定”路径；
- 所有疑似有害摄入至少输出 `CONTACT VET NOW`；
- 出现生命危险信号时输出 `EMERGENCY NOW`；
- 信息不完整时明确无法安全排除风险；
- 固定提醒隔离物品、保留包装和成分，不自行催吐、用药或强行喂食喂水；
- 生成可复制的误食沟通摘要。

### 5.7 日常健康百科

- 适合喂养、环境、行为和日常观察。
- 常见问题具有本地科普卡。
- 模型已配置时，自由问题通过 `wiki` 任务回答。
- 模型不可用时使用本地卡片或通用保守说明。
- 疑似误食转到误食页；危险信号转到紧急行动页。
- 不提供诊断、处方或个体化治疗替代方案。

### 5.8 紧急行动页

- 显示触发的危险信号。
- 行动顺序为：电话确认接诊、准备病例与药物/包装资料、安全转运、持续观察。
- 提供复制危险信号和地图搜索入口。
- 地图入口仅执行搜索，不保证距离、营业时间或接诊能力。
- 页面不调用 AI。

## 6. 本地数据生命周期

当前写入 `localStorage` 的健康相关数据：

- `consultDraft`
- `consultData`
- `consultAnswers`
- `consultResult`
- `emergencySymptoms`
- `toxinDraft`

要求：

- 新写入数据使用 `__miguEnvelope` 包装；
- 默认过期时间为 24 小时；
- 读取到过期数据时立即删除并返回空值；
- 用户可以主动清除全部本机记录；
- 存储失败不能阻断危险信号判断或当前流程；
- `consultData` 必须记录病例创建时的处理模式、AI 授权状态与授权时间；聊天页不得把旧病例或本地模式病例自动发送给后来启用的模型；
- 不存在服务端病例库或跨设备同步。

## 7. AI 与 API 规格

### 7.1 服务端任务

`POST /api/assist` 只接受：

- `triage_questions`
- `triage_result`
- `triage_followup`
- `wiki`

请求正文必须恰好包含 `task` 和 `messages`。消息只允许 `user`、`assistant`，最后一条必须是 `user`。消息数量、单条长度、总长度和 HTTP 正文大小均有限制。

浏览器不得发送：

- `system` 或 `tool` 角色；
- 模型名；
- 系统提示词；
- 工具调用字段或其他控制字段。

服务端在 `prompts.py` 中按 task 注入系统提示词。

### 7.2 模型

- 默认：`deepseek-v4-flash`
- 可选服务端覆盖：`DEEPSEEK_MODEL`
- thinking：显式 `disabled`
- 结构化任务使用 JSON Object 输出
- API Key 只从项目目录的 `.env` 读取

### 7.3 输出安全

- `triage_questions` 必须是含 2–3 个字符串的 `questions` 数组。
- `triage_result` 必须精确匹配规定字段和风险枚举。
- 文本字段、数组项、数量和长度均受限。
- 重复 JSON 键、代码围栏、NaN/Infinity、额外字段和空 choices 均不可信。
- 输出中的自行催吐、双氧水/盐水、刺激咽喉、处方式剂量、强行或针管喂食喂水等建议会被丢弃。
- `triage_result` 的格式或安全校验失败时固定返回 `CONTACT_VET_NOW`。
- 上游传输失败使用 `{error, code}` 错误协议；浏览器再采用本地保守提示。

## 8. 本地服务安全边界

- 只监听 `127.0.0.1`。
- 静态根固定为 `api_proxy.py` 所在目录。
- 禁止目录列表。
- GET/HEAD 仅允许六个页面、favicon、暖色主视觉和两个共享 assets 文件。
- `.env`、`.git`、源码、测试、文档、历史 `app.py` 和其他未列出的路径返回 404。
- `.env` 只显式加载项目目录文件，不向父目录搜索。
- 保留 CSP、防 MIME 嗅探、防 iframe 和无 referrer 等响应头。

## 9. 验收状态

当前自动化验证：

- `python -m unittest discover -s tests -v`：24 项通过；
- `node --test tests/test_frontend_safety.cjs`：3 项通过；
- `python -m py_compile api_proxy.py request_validation.py prompts.py tests/test_api_proxy.py`：通过；
- 静态测试覆盖六个页面的资源存在性和 viewport；
- API 测试覆盖任意 cwd、GET/HEAD 白名单、敏感路径、task/角色/MIME、结构化结果、危险建议和错误协议。

自动化测试不构成医疗有效性验证，也尚未覆盖完整浏览器端到端路径、真实设备矩阵或真实 DeepSeek 可用性。

## 10. 未实现与发布门槛

未实现：

- 账号、登录和权限；
- 云数据库、多宠物档案和跨设备同步；
- 真实医院目录、电话与营业状态；
- 通知、订阅、支付；
- 公网认证、限流、TLS、监控、审计、备份和生产密钥管理；
- 在线执业兽医审核和人工升级流程。

在任何公开发布之前必须：

1. 由执业兽医复核危险信号、三段阈值、误食规则、固定文案和服务端提示词；
2. 完成隐私政策、数据最小化、第三方模型告知、留存与删除方案；
3. 增加认证、授权、速率限制、监控、告警、内容审核和故障降级；
4. 完成真实浏览器端到端测试、可用性测试和无障碍验收；
5. 明确医院搜索结果的责任边界，禁止暗示实时接诊能力。
